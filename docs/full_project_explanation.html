Full Flow

User opens Streamlit.

The app loads from streamlit_app.py. The user works in the browser, not the terminal.

User enables Ollama.

The sidebar has Use Ollama and an Ollama model field. The default model is llama3.2:1b.

User enters session details.

Student name, session ID, and subject are optional. If blank, the app still runs.

User uploads required JSON.

The app requires activity JSON and attendance JSON for each report.

User uploads optional media and documents.

The app accepts video, audio, and homework PDFs as supporting files.

Streamlit saves files into data/.

Uploaded files are cleaned, saved, and prepared for the backend pipeline.

Streamlit calls main.py.

This starts the backend analysis pipeline.

Feature extraction runs.

Video, audio, activity, attendance, and homework are analyzed separately by modules inside src/.

Ollama synthesizes report text.

The extracted metrics are sent to local Ollama. Ollama creates parent narrative, weekly progress, and tips.

Reports are generated.

The app writes outputs/report.json, outputs/report.html, and outputs/report.pdf.

Streamlit displays the preview.

The user can review the result and download PDF, HTML, or JSON.

Source Modules

Why This Is Multimodal

The project is multimodal because it combines several different kinds of input into one report.

Video

Analyzed with OpenCV to estimate focus using face visibility and position.

Audio

Analyzed for speech duration, pause patterns, fluency, WPM, and transcript when available.

Activity JSON

Used for quiz correctness, concept mastery, canvas completion, and time taken.

Attendance JSON

Used for attendance rate, missed classes, and current streak.

Homework PDFs

Parsed for text, topics, completion status, delay status, and quality.

Ollama LLM

Uses extracted metrics to synthesize a parent-friendly narrative and tips.

Ollama LLM Synthesizer

The final version uses local Ollama only. No cloud API keys are needed.

ollama pull llama3.2:1b

The app sets these values internally when Ollama is enabled:

LLM_PROVIDER=ollama
OLLAMA_MODEL=llama3.2:1b
OLLAMA_URL=http://localhost:11434/api/generate
LLM_MAX_OUTPUT_TOKENS=300

What The LLM Receives

The LLM does not receive raw video or raw audio. It receives compact extracted metrics such as focus score, speech summary, attendance summary, homework status, strengths, and weak concepts.

What The LLM Produces

  • Exactly two parent narrative paragraphs.
  • One weekly progress summary.
  • Exactly three actionable tips.

How To Explain It

Use this as your interview or submission explanation:

This is a multimodal offline session-insights pipeline. It takes video, audio, activity JSON, attendance JSON, and homework PDFs. Each modality is processed separately using open-source tools. Video is analyzed with OpenCV for focus, audio is analyzed for fluency and pauses, homework PDFs are parsed with PyMuPDF, and activity/attendance JSON is aggregated into concept and consistency metrics. Then the extracted metrics are passed to a local Ollama LLM, which synthesizes a parent-friendly narrative, weekly progress, and actionable tips. Finally, the system outputs structured JSON, styled HTML, and a PDF report.

Honest Limits

These points are good to mention because they show engineering maturity.

  • Focus detection is estimated through face visibility and centering, not full gaze tracking.
  • Audio fluency is estimated using duration, pauses, speech rate, and transcript when available.
  • Homework quality is rule-based using text length, topic keywords, completion words, and delay words.
  • The LLM is used for report synthesis, not for raw feature extraction.
  • The current app is a prototype, so production scaling would require job queues, object storage, databases, and worker pools.
